  Secret Management (IMPORTANT)
------------------------------------------------------------

{{- if .Values.externalSecrets.enabled }}
  External Secrets Operator is ENABLED.
  Secrets are synced from: {{ .Values.externalSecrets.secretStoreName }}
  Remote path: {{ .Values.externalSecrets.remoteSecretPath }}

  Verify the ExternalSecret status:
    kubectl get externalsecret -n {{ include "ai-resume-analyser.namespace" . }}
    kubectl describe externalsecret {{ include "ai-resume-analyser.fullname" . }}-secrets \
      -n {{ include "ai-resume-analyser.namespace" . }}

  Required keys in AWS Secrets Manager at "{{ .Values.externalSecrets.remoteSecretPath }}":
    database_url, redis_url, celery_broker_url, celery_result_backend,
    secret_key, openai_api_key

{{- else }}
  WARNING: External Secrets Operator is DISABLED.
  A plain Kubernetes Secret was created from values.secrets.
  DO NOT use this in production with real credentials committed to source control.

  For production, enable External Secrets Operator:
    1. Install ESO:
       helm repo add external-secrets https://charts.external-secrets.io
       helm install external-secrets external-secrets/external-secrets \
         -n external-secrets --create-namespace

    2. Create a ClusterSecretStore pointing to AWS Secrets Manager.

    3. Store secrets in AWS Secrets Manager under the path configured in
       values.externalSecrets.remoteSecretPath.

    4. Re-deploy with:
       helm upgrade {{ .Release.Name }} . \
         -f values-prod.yaml \
         --set externalSecrets.enabled=true

  Alternative: Bitnami Sealed Secrets
    kubeseal --fetch-cert --controller-namespace=kube-system > pub-cert.pem
    kubectl create secret generic {{ include "ai-resume-analyser.fullname" . }}-secrets \
      --dry-run=client -o yaml | \
      kubeseal --cert pub-cert.pem -o yaml > sealed-secret.yaml
    kubectl apply -f sealed-secret.yaml
{{- end }}
